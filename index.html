ITERATION

迭代路径与关键决策

从验证可行性到扩展出行场景，5 个版本持续演进

V1.0基础查票能力
验证 MCP 协议可行性，跑通核心链路
V1.1模糊日期解析 + 快捷指令
6 版提示词迭代，解决"明天""下周一"等 NLP 规则不准问题
V1.2多轮记忆 + 无票推荐
降低用户重复输入成本，自动推荐中转或邻近日期
V1.3周边搜索 + 路线规划
集成高德 MCP，将出行场景从"查票"延伸至完整旅程
V2.0用户偏好记忆 + 主动提醒（规划中）
从"响应式"升级到"主动服务"
关键决策
  1. 1
    只查不买 — 明确能力边界，规避交易合规与支付风险
  2. 2
    混合架构 — 核心查询走云端大模型，敏感数据走本地 Ollama
  3. 3
    MCP 优先 — 用标准化协议替代自研工具链，降低长期维护成本

CHALLENGES

遇到的问题与解决思路

三类核心问题，每一个都倒逼出更健壮的工程方法

问题一：提示词迭代成本高
问题描述解决方案
模糊日期识别不准，"明天""下周一"常出错 建立结构化测试集，每次迭代后回归验证
输出格式不稳定，时而纯文本时而表格 强制结构化输出，用 Emoji 做视觉分层
问题二：模型调用工具不稳定
问题描述解决方案
明确需要查酒店，AI 却不调用高德工具 提示词中明确"触发条件"和"工具映射规则"
调用中状态卡死 检查 API Key 类型（需 Web 服务类型），降级 MCP 版本
问题三：多 MCP 协同时的意图识别
问题描述解决方案
"查票+查酒店"一次性完成，容易漏掉其中一个 设计链式调用模板，在提示词中预设组合场景
